# DBAuto 下一版本前端 UI 优化方案（v-next）

> 范围：仅前端 UI/UX 层面，不改变任何业务逻辑与接口契约。
> 基线：当前版本已完成「liquid-glass 设计令牌化 + 浅色主题修复 + 想看同步功能移除」。
> 技术栈约束：vanilla JS + 单文件构建（build.sh），不引入框架。

### 7.1 2.1 设置页重构 — ✅ 实施

  - `body.html` 删除 `#overviewModule` 整块；页面副标题改为「配置数据源、转存服务与认证信息」。
  - `dashboard.js` 精简为纯共享数据源：仅保留 `fetchDashboardAll` / `loadDashboard`（顶栏版本号更新，兼容 init.js 与 SSE 调用点）与共用的 `esc()`，删除全部死渲染函数与骨架屏逻辑。
  - 同步清理 main.css 中约 160 行孤儿样式（`.overview-*`、`.status-dot`、`@keyframes pulse/pulseReduced`、密度与断点残留引用）。
- **「账号与同步」空壳分组撤销**：管理认证卡并入「数据源与转存」组，设置页由两组折叠收敛为一组 + 保存条。
- **锚点快速导航 → 经评估不实施**：合并后仅剩一个 settings-group，锚点导航失去对象；如未来分组超过 3 个再引入 chips 导航。

### 7.2 侧边栏 / 顶栏重复功能评估 — 结论：均为合理冗余，保留
| 疑似重复 | 结论 |
|---|---|
| 侧边栏导航 ↔ 移动端 bottom-nav | 响应式结构性重复（≤1024px 侧边栏转为抽屉、bottom-nav 显示），必需，保留 |
| 顶栏搜索框 ↔ ⌘K 命令面板 | 功能互补：搜索框定位资源（listbox 下拉），⌘K 面板定位页面与快捷操作；保留两者 |
| 定时页「转存设置」↔ 设置页 | 职责不同：前者是执行参数（上限/时间/筛选器），后者是服务连接配置；保留现状 |

### 7.3 2.3 移动端表格卡片化 — ✅ 实施
- 方案：CSS-only（≤640px 时 `display:block` + `td[data-label]::before` 列头），DOM 仅补充 data-label 属性：
  - 概览页最近转存表（overview.js）：时间 / 状态两列补标签；
  - 历史页执行历史表（history.js）：状态 / 类型 / 结果 / 时间四列补标签，详情列整行展示。
- 详情展开行（hist-detail-row）与空态行（colspan）在移动端保持通栏不受卡片布局影响。

### 7.4 5.3 backdrop-filter 性能降级 — ✅ 实施
- 新增 `--surface-solid` 双主题令牌（深色 #16171c / 浅色 #ffffff）+ `@supports not (backdrop-filter…)` 兜底：不支持的环境磨砂面退化为实底，避免半透明面板叠流动光斑导致对比度不足与掉帧。

### 8.6 追加修复：概览页日志栏在桌面态被自动折叠至 48px — ✅ 实施

**问题（走查中发现，与 410498f / 58fcfd4 同类 P0 缺陷）**

1280px 桌面视口下，概览页右侧「执行日志」栏被压成 **48px**，只剩一条窄边，
核心功能（转存进度 / 日志）不可见。

**根因（三处叠加，缺一不可）**

1. `tabs.js` 中 `switchTab('overview')` **无条件**调用 `collapseLogPanel()`，
   而概览正是默认首页 —— 桌面用户一进站日志栏就被折叠；
2. `.log-toggle-btn` 的 CSS 存在，但 **DOM 里从来没有这个按钮** —— 是死样式，
   折叠后没有任何展开入口；
3. `toggleLogDrawer()`（FAB 点击）只切 `.open`（移动端抽屉态），桌面态点 FAB 毫无反应。

三者叠加 → 桌面概览页日志栏**折叠后无法还原**，等同功能缺失。

**修复**

- `tabs.js`：自动折叠加窄屏判定 `isNarrowViewport()`，并尊重用户显式选择
  `userSetLogPanelState()`（本地已存过折叠偏好才自动收起）；
- `body.html`：补上 `#logToggleBtn` 折叠态展开按钮（带 `aria-expanded`/`aria-controls`）；
- `log.js`：新增 `_syncLogPanelA11y()`，统一同步按钮 aria 与标题、并在桌面折叠态显示 FAB 作为备用入口；
- `init.js`：`toggleLogDrawer()` 在桌面态改为「展开折叠的日志栏」，窄屏仍走抽屉；
- `main.css`：折叠态补 `position:relative` 作为按钮定位上下文，按钮 `:focus-visible` 焦点环。

**验收**：1280px 下日志栏宽度 48px → **290px**（内容完整可见）；
折叠 → 展开往返正常；折叠态展开按钮与 FAB 均可见；390px 移动端底栏导航正常。
回归断言已写入 `tests/test_build.py`（展开入口存在 + 桌面不得无条件自动折叠）。

### 9.2 实施的改动

**1. 新增分区快速定位（chips）**
顶部 4 个 chip 对应「数据源 / 转存服务 / 转存路径 / 认证与缓存」，点击即展开目标分组并平滑滚动定位。
滚动时通过 IntersectionObserver 反查当前可见分组、联动高亮。

> 实现细节：点击触发的平滑滚动会持续产生交叉回调，若不挂起 spy，回调会用滚动途中的
> **中间分组**覆盖点击选中的 chip（实测「点转存路径、高亮停在转存服务」）。
> 因此在跳转期间挂起 spy（`suspendSettingsJumpSpy`），滚动结束再恢复。

**2. 分组头升级为「图标 + 名称 + 说明 + 条目数」**
原 2 分组重构为 4 个语义分组，每个分组头带一句话说明与条目数徽标，折叠态下也能判断内容。
`summary` 高 47px → 62px，单位信息密度提升。

**3. 卡片等高 + 底部动作位贴底**
同组网格 `align-items:stretch`，卡片内部 `flex-direction:column`，卡片动作区
（如「刷新豆瓣缓存」）`margin-top:auto` 贴底。实测行内卡片高度由 343/303 参差 → 完全一致。

**4. 结构化字段说明**
新增 `.form-hint` 组件替换原先的 inline `style="font-size:12px..."` 写法，
为 6 处关键字段补充说明（PanSou 用途、QAS 用途与 Token 语义、三类路径规则、认证改动后果等）。

**5. 保存条重构为「说明 + 主按钮」**
替换原来的空卡方案，并在用户改动任意输入后切换为橙色「有未保存的改动」提示，
保存成功后自动复位——让保存动作与表单改动建立可见关联。

> 方案取舍：**未采用 `position:sticky` 吸底**。实测 sticky 悬停时会在滚动中段盖住
> 「转存路径」的说明文字与下一张卡片标题（1200/1280/1024 三档均复现），
> 因此改为常驻文档流，位置固定在分组列表之后。

**6. 修复 `#icon-lock` 未定义**
补齐锁形图标 symbol，并把「管理认证」的「刷新豆瓣缓存」按钮拆分为独立的
「缓存维护」卡片（原按钮挤在卡片标题行右侧，与标题争抢空间）。

### 9.3 响应式策略

栅格断点统一到全局 `1500 / 1350 / 1200 / 1024 / 640`：

- **>1200px**：双列（`auto-fit minmax(300px,1fr)`），单卡分组限宽 `--set-card-max: 560px`
  （避免出现 736px 宽的巨型单卡）；
- **≤1200px**：日志栏转为覆盖层、主列反而**变宽**，此时用 `auto-fit` 让容器宽度决定列数，
  而非硬性降级为单列（硬性单列会把卡片拉成 900px+ 的巨型单卡）；
- **≤1024px**：侧栏亦收起，主列最宽，保持两列更省纵向滚动；
- **≤640px**：强制单列；chips 改为横向滚动不换行；分组说明允许换行；隐藏条目数徽标。

## 十、第六批实施结果（本轮）— 概览页显示密度与优先级

> 触发：issue #8「对概览页的显示密度和优先级提出优化方案」。
> 基线数据全部来自 `scripts/check_overview_dom.py`（真实浏览器 + 确定性桩数据），
> 而非主观判断。

### 10.1 走查发现的缺陷（渲染实测）

| # | 缺陷 | 实测证据（900px 高视口） |
|---|---|---|
| 1 | **首屏被推到折叠线以下** | 「热门推荐」面板在 1280/1440 从 y=599 才开始；`contentH` 845（1920）→ 1135（1024/900/760），768 以下内容整体溢出视口 |
| 2 | **KPI 卡高度随窗口漂移** | 1920/1600 为 93/103px，1440/1280 为 132px；1024/760 折成 2×2 后变成 81/81/93/93（单行卡 81、双行卡 93 参差） |
| 3 | **一屏内只有 8 条最近转存** | `items.slice(0, 8)` 硬截断 + 「最近 8 条」文案 + 「查看全部」入口 + 320px 面板内滚动，同一份数据被截了三层 |
| 4 | **状态语义错误** | 存储里 `status` 为 `exists`（幂等跳过）的条目，一律渲染为绿色 `ov-badge-success`「已转存」，把跳过误报成成功 |
| 5 | **空日期打乱排序** | `date` 为空串的条目在 `localeCompare` 降序下排到列表**最前**，并显示为 `-`（与真实日期不可区分） |
| 6 | **热门推荐海报恒为占位图** | 后端契约为 `items:[{poster,title,year,rating}]`，前端却读 `results/poster_path/release_date/vote_average`，`poster` 恒为空 → 每张卡只剩 36px 图标 |
| 7 | **移动端分类前缀被压成竖排单字** | ≤640px 卡片化后 `.ov-table-cat` 实测宽度 **10px**（「电影」二字竖排），截图确认 |
| 8 | **`ov-dot-warn` / `ov-badge-skip` 等类无样式** | `renderOvHealth` 产出 `ov-dot-warn`，CSS 只定义了 `ov-dot-ok/fail/unknown` |
| 9 | **死 CSS** | `.ov-status-dot`、`.ov-st-*`、`.ov-todo-danger/-warning/-info`、`.ov-rec-rating/-btn`、`.ov-cell-title`、`.ov-health-item/-name/-val` 均已无引用 |
| 10 | **`data-density="standard"` 无令牌声明** | 密度令牌只在 comfortable/compact 下覆盖，缺 `standard` 分支（用户切回标准档时不会复位） |

### 10.2 实施的改动

**1. 信息架构：从「三段式竖排」改为「首屏两列」**

```
┌─ 转存概览（指标行 + 服务状态/待办）────┬─ 最近转存 ────────────┐
│ 今日转存 3      共 10 次成功   [去发现] │ 标题 时间 状态 库内 链接 │
│ 近 7 天成功率 91%  成功 10 · 失败 1     │ …（10 行，全量可见）    │
│ 下次调度 转存 … · 检测 …      [立即执行]│                        │
│ ── 服务状态 | 待办 ─────────────────── │ ── 「库内」含义说明 ──── │
├────────────────────────────────────────┴────────────────────────┤
│ 热门推荐（与 TMDB 页共享数据源）                                  │
└─────────────────────────────────────────────────────────────────┘
```

- 旧的四张等宽 KPI 卡 → **行式指标列表**（标签 + 值 + 副信息 + 动作，行高固定 54px）。
  卡片式布局在中间宽度必须折成 2×2，是缺陷 2 的根因；行式布局没有这个退化路径。
- 「转存库总数」卡片与「最近转存」面板标题重复，**移除**，改由面板副标题表达
  （`最近 10 条 / 共 13 条`）与概览头部（`转存库 13 条 · 上次成功`）。
- 「热门推荐」与「最近转存」同处首屏右侧/顶部，不再被推到折叠线以下。

**2. 首次给出「三、优先级」判断**（issue 标题的后半句）

- **决策区**（服务状态 + 待办）经评估后与指标区同列：它决定「要不要现在动手」，
  必须留在首屏；但常态项（调度运行中、上次成功、版本号）压成一行
  `运行状态：全部正常 · v1.1.0`，只把「未配置调度 / 上次失败」展开成独立行。
- **信息区**（最近转存 10 行）从 8 条提升到面板容量，去掉面板内滚动，
  「查看全部 → 历史记录」成为唯一出口。
- **消费区**（热门推荐）保留数据结构但降级到首屏之后，高度收敛为一行海报卡。

**3. 概览两列自适应改用「主列实测宽度」驱动**

`@media(max-width:1350px)` 这类 viewport 断点在 1280~1440 区间会误判：
Playwright 的 `viewport:{width:1440}` 因滚动条得到 `innerWidth=1425`，媒体查询命中，
但主列实际宽度（846~920px）完全放得下两列。侧栏折叠、日志栏宽度同样改变主列宽度。
改为 `initOverviewViewport()` 用 `ResizeObserver` 观测 `.main` 宽度，设置
`.app[data-ov-narrow]`，阈值 `OV_NARROW_PX = 860`。

**4. 语义与数据修复**

- `ovRecentState()`：`ok/done` → 已转存、`exists/skipped` → **已存在跳过**、
  `fail/error/invalid` → 失败、`downloading/running` → 进行中，未知时回退看 `shareurl`。
- `ovDateShort()`：空值显示 `—`，否则 `MM/DD HH:MM`；排序把空日期压到末尾。
- `renderOvRecs()`：按契约读 `items/poster/year/rating`，`poster` 为完整 URL 时直接用，
  否则拼 `TMDB_IMG_BASE`。
- 补齐 `ov-dot-warn`、`ov-dot-error`、`ov-badge-skip/-fail/-run/-muted`、
  `ov-todo-icon-*`、`ov-rec-skel` 等缺失样式；删除 10 处死 CSS。
- 补齐 `html[data-density="standard"]` 令牌分支。

**5. 窄屏 640px 卡片化修复**

`.ov-table` 改为 `display:block`、去掉 `table-layout:fixed`（卡片形态下固定列宽
会把 `.ov-table-cat` 压成 10px），分类前缀 `flex:0 0 auto` 且文案改为
`电影 / 剧集 / 综艺`（原为 `movie/tv`）。
